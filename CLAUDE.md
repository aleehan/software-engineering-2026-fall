# Gamekeeper

Десктопное приложение для Windows 11, которое блокирует CS2 после N сыгранных за день каток.

Пользователь изучает TypeScript: при работе объясняй, что делаешь и почему, особенно TS-конструкции (типы, дженерики, модули, async/await).

## Стек

- Electron + React + TypeScript (шаблон electron-vite)
- Drizzle ORM + SQLite (better-sqlite3)
- electron-builder (сборка установщика)

## Архитектура

```
src/
  main/                 — main-процесс Electron
    core/               — бизнес-логика БЕЗ импорта 'electron' (тестируется отдельно)
      gsi-server.ts     — HTTP-сервер, принимающий POST от CS2 Game State Integration
      match-counter.ts  — подсчёт завершённых каток
      rules-engine.ts   — лимит, состояние блокировки, сброс в 05:00
      enforcer.ts       — поиск и закрытие cs2.exe
      db/               — схема Drizzle, миграции, репозитории
      games/cs2/        — путь к Steam/CS2, установка gsi cfg, разбор payload
    index.ts            — точка входа: окно, трей, автозапуск, IPC, single-instance
  preload/              — мост window.gamekeeper через contextBridge
  renderer/             — React UI: Главная, Настройки, История
```

Правило: `src/main/core/*` не импортирует `electron`. Всё, что связано с Electron (окно, трей, уведомления, app.getPath), живёт в `src/main/` и передаётся в core через параметры/интерфейсы.

## Логика

- **GSI**: при запуске проверить/установить `gamestate_integration_gamekeeper.cfg` в `<CS2>/game/csgo/cfg/` с уникальным токеном. Путь Steam — из реестра (`HKCU\Software\Valve\Steam\SteamPath`), библиотеки — из `steamapps/libraryfolders.vdf` (CS2 appid 730).
- **Засчитывание катки**: переход `map.phase` → `gameover`; только соревновательные режимы (competitive, premier, wingman); `player.steamid` должен совпадать с `provider.steamid` (собственный SteamID, а не наблюдение). Дедупликация: одна катка — одна запись.
- **Лимит**: пользователь выбирает 1–10 каток в день.
- **Достижение лимита**: после последней катки — уведомление, cs2.exe закрывается через настраиваемое время. По умолчанию 0 — сразу на экране итогов (решение пользователя: за 2 минуты ожидания можно найти ещё одну игру).
- **Блокировка**: пока активна, cs2.exe закрывается при каждом запуске (проверка каждые 3 с).
- **Новый матч после исчерпания лимита** (если задержка > 0): закрывается сразу, не защищён.
- **Посреди матча не убивать**: защищён только матч, который уже шёл в момент перехода из `allowed` (лимит ужесточили вручную посреди игры); после его окончания игра закрывается. «Идёт матч» — только по свежим данным GSI (< 65 с).
- **Сброс счётчика**: ежедневно в 05:00 по локальному времени.

## Защита (средний уровень)

- Автозапуск с Windows.
- Закрытие окна сворачивает в трей, а не завершает приложение.
- Single-instance lock: второй экземпляр не запускается, а показывает окно первого.
- Выход из приложения, снятие блокировки, ослабление лимита (увеличение N, увеличение задержки) — только по паролю + задержка 10 минут перед применением. Автозапуск отключить из приложения нельзя вообще.
- Ужесточение (уменьшить N, уменьшить задержку, отменить ожидающее изменение) — сразу, без пароля. Уменьшение отменяет ожидающее повышение того же вида.
- Реализация: `core/protection.ts` (`ProtectionService`), пароль — scrypt со солью (`core/password.ts`), очередь — таблица `pending_changes`, применение — `applyDue()` раз в 5 с из main. Повторный запрос того же вида заменяет старый.
- «Снять блокировку» = `settings.unlocked_until` до ближайших 05:00. Выход по истечении задержки — `app.quit()`; запросы на выход с прошлого запуска отменяются при старте.
- Пункт трея «Выход…» только открывает окно. Выключение Windows не блокируется (`session-end`).

## Фронтенд: дизайн через unslop

Для дизайна интерфейса используем скилл **unslop** (плагин `unslop@heydamir`).

1. Сначала собрать рабочие экраны (Главная, Настройки, История) с простой вёрсткой — функциональность важнее вида.
2. Затем прогнать каждый экран через `/unslop`.
3. Направление визуала согласовать с пользователем **до** правок дизайна — не начинать редизайн без его подтверждения.

### Согласованное направление (2026-11-20): «Судья и счёт»

- **Продукт.** Считает соревновательные катки в CS2 и закрывает игру, когда дневной лимит исчерпан, — для игрока, который сам решил играть меньше.
- **Характер.** Твёрдый, честный, спокойный.
- **Мир.** Судейский протокол, табло, секундомер. Тёмная тема, нейтральный графит; цвет — только в главном элементе экрана.
- **Момент.** Катки дня как засечки на табло: сыгранные заполнены, оставшиеся пустые; рядом «2 из 5». Акцент — сигнальный жёлтый судейской карточки.
- **Фирменная деталь.** Засечки-счётчик — везде, где считаются катки (главная, история по дням), и больше нигде.

## Команды

- `npm run dev` — запуск в режиме разработки
- `npm run typecheck` — проверка типов
- `npm test` — юнит-тесты (Vitest). Тесты лежат рядом с кодом: `*.test.ts`. Vitest запускается внутри Electron в режиме Node (`scripts/vitest-electron.mjs`), поэтому тесты могут использовать better-sqlite3 (база `':memory:'` + миграции из `drizzle/`). Модуль `electron` в тестах недоступен — тестируем только `core/`.
- `npm run build:win` — установщик NSIS в `dist/` (`npm run build:unpack` — распакованная версия для проверки)
- `npm run icons` — перерисовать иконки из `scripts/icons/*.svg`
- `npm run db:generate` — сгенерировать SQL-миграцию после изменения `src/main/core/db/schema.ts`

## База данных

- Файл: `%APPDATA%\gamekeeper\gamekeeper.db`. Миграции применяются автоматически при старте (`openDatabase`).
- Миграции лежат в `drizzle/` и коммитятся; в сборку попадают через `extraResources`. Уже закоммиченные миграции не редактировать — только генерировать новые.
- `better-sqlite3` — нативный модуль, собран под Electron (`electron-builder install-app-deps` в postinstall). Обычный Node его не загрузит; для скриптов использовать `ELECTRON_RUN_AS_NODE=1 electron script.js`.

## CS2 / GSI

- GSI-сервер: `127.0.0.1:47815` (`DEFAULT_GSI_PORT` в `core/games/cs2/integration.ts`). Токен генерируется один раз и хранится в `settings.gsi_token`.
- Конфиг `gamestate_integration_gamekeeper.cfg` ставится при каждом старте приложения, если содержимое отличается. CS2 читает cfg только при своём запуске — после установки игру нужно перезапустить.
- Засчитывание катки — `MatchCounter` (`core/match-counter.ts`): переход фазы в `gameover` из известной фазы + соревновательный режим + за матч хотя бы раз `player.steamid === provider.steamid` с командой CT/T. Проверять SteamID только в момент gameover нельзя: мёртвый игрок наблюдает за тиммейтом.
- Ручная проверка без игры: POST JSON на сервер с токеном из базы (см. формат в `gsi-payload.ts`).

## Сборка

- Иконки: `scripts/icons/icon.svg` → `build/icon.png` (из него electron-builder делает .ico) и `resources/icon.png`; `tray.svg` → `resources/tray.png` + `tray@2x.png`.
- Установщик per-user (без прав админа), не подписан. `build/installer.nsh` при удалении стирает запись автозапуска `HKCU\...\Run\Gamekeeper`.
- Автозапуск: запись `Gamekeeper` с флагом `--hidden`. Проверять через `executableWillLaunchAtLogin` — `openAtLogin` на Windows всегда false из-за сравнения args.
- Распакованная сборка из `dist/win-unpacked` при запуске регистрирует автозапуск на свой путь — после проверки удалить: `reg delete HKCU\Software\Microsoft\Windows\CurrentVersion\Run /v Gamekeeper /f`.
## FACEIT

- Матчи FACEIT засчитываются в лимит и показываются в истории. Два источника: GSI (сразу на экране итогов, если CS2 сообщает соревновательный режим — для FACEIT это не проверено) и FACEIT Data API (`core/faceit/`). Синхронизация: при старте, раз в 3 мин, через 1 и 2.5 мин после каждой GSI-катки, после подключения аккаунта.
- Склейка: FACEIT-матч + GSI-катка на той же карте в пределах ±10 мин = одна запись (`faceit_match_id` дописывается к GSI-записи). Иначе новая запись `source='faceit'`, она идёт в лимит.
- API (сверено с живыми ответами, `scripts/faceit-probe.mjs`): `Authorization: Bearer <key>`; `/players?nickname=`; `/players/{id}/history?game=cs2` — время в секундах, команды `faction1/faction2`, `results.winner` и `results.score` (раунды); карта и K/D — только в `/matches/{id}/stats` (`rounds[0].round_stats.Map`, `player_stats.Kills/Deaths` строками). Неверный ключ → `400 {"error":"invalid_token"}`.
- Аккаунт FACEIT: первое подключение — сразу; смена/отключение — ослабление (`change_faceit`, пароль + 10 мин). Ключ хранится в `settings.faceit_api_key` локально и в интерфейс не отдаётся.
- `.faceit-key` (в .gitignore) — ключ только для скрипта разведки.

## Разработка рядом с установленной версией

`GAMEKEEPER_PROFILE=test npm run dev` (в cmd: `set GAMEKEEPER_PROFILE=test&& npm run dev`) — отдельная папка данных `%APPDATA%\gamekeeper-test` (своя база и single-instance lock), GSI на порту 47816, конфиг CS2 не трогается, cs2.exe не закрывается. Без этого dev-запуск конфликтует с установленным Gamekeeper (общая база, замок, порт и токен в cfg). Установленный экземпляр не закрывать — это защита пользователя.
